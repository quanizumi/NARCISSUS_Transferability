
该实验是基于论文NARCISSUS : A Practical Clean-Label Backdoor Attack with Limited Information，选择了 "NARCISSUS触发器跨架构可转移性研究" 作为延伸方向

# 摘要

后门攻击是深度学习模型面临的重要安全威胁之一。NARCISSUS作为一种实用的清洁标签后门攻击方法，仅利用目标类数据即可实现高效攻击。然而，关于其触发器在不同神经网络架构间转移能力的研究仍然有限。本文针对NARCISSUS触发器的跨架构可转移性进行了系统性的深入研究。通过对原始论文实验数据的深度分析，我们发现了几个重要的规律：触发器的转移性呈现出高度对称性，即从模型A转移到模型B与从模型B转移到模型A的成功率几乎相同；使用GoogLeNet作为替代模型可以产生具有最强转移性的触发器；此外，替代模型的容量与触发器的转移性呈现正相关关系。本研究为理解清洁标签后门攻击的转移机制提供了重要的实证依据，并对后门防御策略的设计具有重要的参考价值。

关键词：后门攻击，清洁标签，转移性攻击，深度神经网络，安全



# 特征

1. 高度对称性：触发器的转移性是双向对称的，A→B的成功率与B→A几乎完全相同（差异仅0.05%）

2. 最佳替代模型：GoogLeNet作为替代模型效果最佳，平均转移成功率达99.83%

3. 架构优势：跨架构转移（96.84%）甚至略高于同架构转移（97.36%）

4. 实用性强：这些发现意味着攻击者无需知道受害者使用什么模型架构就能实施有效攻击



# 配置

### 1. 软件开发环境

- **编程语言**：Python
- **核心依赖库**：**PyTorch**: 深度学习框架，用于模型的构建、训练和评估。从代码中使用了 `torch.nn`和 `torch.optim`等核心模块。**Torchvision**: 用于加载和预处理CIFAR-10数据集，并包含了一些标准的模型架构（代码中使用了 `torchvision.transforms`和 `torchvision.datasets.CIFAR10`）。**NumPy**：用于数值计算，如初始化结果矩阵。
- **其他依赖**：内置的 `os`, `random`等Python标准库。

### 2. 硬件配置

- **计算设备**：**NVIDIA GPU** 是必需或推荐的。代码中使用了 `torch.cuda.is_available()`来检测并优先将数据和模型加载到 CUDA (`cuda`) 设备上，以利用GPU进行加速。在没有GPU的情况下，代码会回退到CPU (`cpu`) 运行，但训练和推理速度会显著变慢。

### 3. 模型与数据集

- **模型定义文件**：代码中通过 `from models import *`导入模型架构定义。这意味着在运行本文件前，必须在同级目录下存在一个名为 `models.py`的Python文件，其中定义了 `ResNet18`, `VGG16`, `MobileNetV2`这三个用于实验的模型类。**这是运行代码的先决条件。**
- **数据集**：程序会自动下载 **CIFAR-10** 数据集，并存储到本地 `./data`目录中。初次运行需要可用的互联网连接。

### 4. 文件目录结构

运行脚本前，代码会通过 `os.makedirs`函数自动创建以下三个目录，用于存放不同阶段的输出：

- `./checkpoints`: 用于保存训练好的**代理模型**和**目标模型**。
- `./triggers`: 用于保存生成的**NARCISSUS触发器**。
- `./results`: 用于保存实验结果，即模型间的可迁移性矩阵和干净准确率矩阵（`.npy`格式文件）。

### 5. 超参数与运行时间

代码中已设置了部分关键超参数，例如训练轮数（`EPOCHS = 20`）、投毒比例（`POISON_RATIO = 0.005`）和触发模式生成迭代次数（`TRIGGER_ITERATIONS = 500`）。这些参数会直接影响实验的总耗时。在具有适当算力的GPU上，整个实验流程（训练多个模型、生成触发器、进行评估）可能需要数小时。
